# Stringee Chat Notification Sample

Flutter sample demonstrating Stringee Chat together with Firebase Cloud
Messaging on Android and Apple Push Notification service on iOS.

The app deliberately does not contain a Stringee access token. Paste a token
issued by your trusted server on the connection screen. A successful token is
stored locally and reused on the next launch; **Logout** unregisters push,
disconnects Stringee, and removes the saved token.

## What the sample covers

- Connect, reconnect from a saved token, disconnect, and logout.
- Register and unregister the current FCM/APNs token with Stringee.
- Foreground, background, notification-open, and token-refresh callbacks.
- Observe Stringee conversation and message change events.
- Create and query one-to-one conversations.
- Read local/latest/before/after conversation pages and total unread count.
- Send, load, edit, pin, delete, and revoke messages.
- Add/remove participants, update conversation name, set roles, send typing
  state, mark as read, and delete a conversation.

The sample uses `stringee_plugin: ^1.3.3` and the current Flutter Gradle plugin
layout. Android targets the Flutter-provided SDK levels with AGP 8.6/Kotlin
2.1; iOS has a minimum deployment target of 15.0 (required by the current
Firebase Apple SDK).

## Install dependencies

```bash
flutter pub get
```

## Configure Firebase

The repository contains Firebase options for the public sample project. To use
your own project, install FlutterFire CLI and regenerate Android/iOS options:

```bash
dart pub global activate flutterfire_cli
flutterfire configure --platforms=android,ios,web
```

Select or register these application identifiers when prompted:

- Android: `com.stringee.chat_notification_sample`
- iOS: the bundle ID configured in `ios/Runner.xcodeproj`

For iOS push delivery, enable **Push Notifications** and **Background Modes →
Remote notifications** for the Runner target, then upload the APNs key or
certificate to both Firebase and the Stringee developer portal.

For Android 13+, the manifest contains `POST_NOTIFICATIONS`; the sample requests
permission at runtime through Firebase Messaging.

## Run

```bash
flutter run
```

Then:

1. Paste a Stringee access token and select **Connect**.
2. Enter a Stringee user ID to create or find a conversation.
3. Open a conversation to exercise message and participant APIs.
4. Select **Logout** when changing users; this also clears push registration.

## Important integration notes

- `FirebaseMessaging.onBackgroundMessage` must point to a top-level function
  annotated with `@pragma('vm:entry-point')`.
- On iOS, Stringee Chat uses the APNs token (`getAPNSToken`) and registers it as
  non-VoIP push. On Android it registers the FCM token (`getToken`).
- When Firebase rotates the token, the sample registers the new value if the
  Stringee client is connected.
- A Stringee access token is sensitive session data. This sample stores it in
  `SharedPreferences` for clarity; production applications should assess
  whether platform-secure storage is required by their threat model.
